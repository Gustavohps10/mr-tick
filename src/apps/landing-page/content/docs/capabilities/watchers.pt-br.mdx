A capacidade `watcher` permite acompanhar atividades e sugerir apontamentos a partir delas. Um addon pode, por exemplo, observar uma chamada de voz ou eventos de um serviço externo.

Declare `watcher` no manifesto. Se o serviço exigir uma conta conectada, declare também `auth` e registre sua autenticação. Não é necessário oferecer uma fonte de dados apenas para guardar credenciais. O exemplo abaixo usa as duas capacidades.

```yaml
id: example-addon
name: Example Addon
version: 0.1.0
author: Example
shortDescription: SDK example
description: Example using the published SDK
capabilities:
  - auth
  - watcher
requiredApiVersion: '>=0.11.0'
```

```ts
import type {
  AddonContext,
  LocalEntryInput,
  LocalOperationIdentity,
} from '@mr-tick/sdk'

export function suggest(
  context: AddonContext,
  workspaceId: string,
  input: LocalEntryInput,
  operation: LocalOperationIdentity,
) {
  return context.core.timeEntries.createSuggestion(
    workspaceId,
    input,
    operation,
  )
}
```

Escolha workspace, conexão de origem, tarefa e atividade explicitamente. `LocalEntryInput` usa segundos e datas ISO. Aloque IDs da operação antes da escrita e os reutilize somente em repetições com conteúdo idêntico. Sucesso significa sugestão local, não confirmação remota.

Eventos garantidos: `timer:start`, `timer:pause`, `timer:resume`, `timer:stop`, `timer:update`, `workspace:changed`. O SDK não oferece um evento geral de inatividade. Registre as assinaturas de eventos durante a ativação e libere os recursos do addon na desativação. Trocas de workspace não desativam o addon.

Consulte [autenticação](/pt-br/docs/capabilities/auth), [OAuth PKCE](/pt-br/docs/apis/oauth-pkce) e [cofre e eventos](/pt-br/docs/apis/vault-and-events).
