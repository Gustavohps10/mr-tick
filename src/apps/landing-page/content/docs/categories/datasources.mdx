# DataSources (Provedores de Dados)

Um **DataSource** é o tipo de Addon responsável por integrar o Mr-tick a ferramentas de gerenciamento de tarefas e projetos (como Jira, Redmine, YouTrack, GitHub Issues ou Azure DevOps).

Ele atua como a ponte de comunicação que o [Motor de Sincronização](/docs/sync-engine) utiliza para executar as fases de **Pull** (download de tarefas e metadados) e **Push** (upload de apontamentos de horas).

---

## 🏗️ Arquitetura de um DataSource

Um DataSource moderno no Mr-tick é registrado dentro do método `activate` do seu Addon e implementa o método `createInstance(context)`, retornando uma instância com seus **Providers**:

1. **`authStrategy` (`IAuthenticationStrategy`)**: Estratégia de autenticação e validação de credenciais.
2. **`tasksProvider` (`ITaskProvider`)**: Responsável por listar tarefas e executar o **Pull** com checkpoints.
3. **`timeEntriesProvider` (`ITimeEntryProvider`)**: Responsável por listar, criar, atualizar e excluir apontamentos de horas (**Push**).
4. **`membersProvider` (`IMemberProvider`)**: Responsável por retornar os dados do membro conectado e usuários.
5. **`metadataProvider` (`IMetadataProvider`)**: Responsável por obter status, prioridades e atividades disponíveis.

```typescript
// 2. Definição do DataSource (Metadata-Driven)
export const MeuDataSource: IDataSource = {
  getConnectionSchema(): AddonSettingsSchema {
    return [
      {
        id: 'credentials',
        label: 'Credenciais & Conexão',
        groups: [
          {
            id: 'auth',
            label: 'Autenticação',
            fields: [
              {
                id: 'serverUrl',
                label: 'URL do Servidor',
                type: 'text',
                scope: 'configuration',
                required: true,
              },
              {
                id: 'apiToken',
                label: 'Token de Acesso',
                type: 'password',
                scope: 'credential',
                required: true,
              },
            ],
          },
        ],
      },
    ]
  },

  createInstance(context: DataSourceContext): IDataSourceInstance {
    return {
      authStrategy: new MinhaAuthStrategy(context),
      tasksProvider: new MinhaApiTaskProvider(context),
      timeEntriesProvider: new MinhaApiTimeEntryProvider(context),
      membersProvider: new MinhaApiMemberProvider(context),
      metadataProvider: new MinhaApiMetadataProvider(context),
    }
  },
}

// 3. Addon Principal (Microkernel: apenas activate e deactivate)
export default class MeuDataSourceAddon implements IAddon {
  public async activate(context: AddonContext): Promise<void> {
    // Registra as preferências dinamicamente ou reaproveita o schema
    context.settings.register(MeuDataSource.getConnectionSchema())

    // Registra o DataSource no sistema
    context.dataSources.register(MeuDataSource)
  }

  public async deactivate(): Promise<void> {
    console.log('[MeuDataSourceAddon] Desativado.')
  }
}
```

## 💡 Melhores Práticas para DataSources

- **Desacoplamento por Providers**: Separe cada responsabilidade (Tarefas, Horas, Membros e Metadados) em classes especializadas que implementam suas respectivas interfaces.
- **Respeito a Checkpoints**: Sempre utilize filtros de data de modificação (`checkpoint.updatedAt`) para minimizar o tráfego de dados no `pull`.
- **Validação de Credenciais**: A autenticação deve ser realizada na `authStrategy`, garantindo que conexões inválidas sejam rejeitadas antes de qualquer sincronização.
- **Configurações via Settings**: Utilize `context.settings.register(...)` para declarar campos de credenciais e configuração sem misturá-los com a lógica de rede.
