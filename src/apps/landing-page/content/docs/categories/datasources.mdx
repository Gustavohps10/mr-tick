# DataSources (Data Providers)

A **DataSource** is an addon that integrates Mr. Tick with task and project management tools such as Jira, Redmine, YouTrack, GitHub Issues, or Azure DevOps.

It provides the communication bridge used by the [Synchronization Engine](/docs/sync-engine) for **Pull** (downloading tasks and metadata) and **Push** (uploading time entries).

---

## 🏗️ DataSource Architecture

A modern Mr. Tick DataSource is registered in the addon's `activate` method and implements `createInstance(context)`, returning an instance with its **Providers**:

1. **`authStrategy` (`IAuthenticationStrategy`)**: Authenticates and validates credentials.
2. **`tasksProvider` (`ITaskProvider`)**: Lists tasks and performs checkpoint-based **Pull**.
3. **`timeEntriesProvider` (`ITimeEntryProvider`)**: Lists, creates, updates, and deletes time entries (**Push**).
4. **`membersProvider` (`IMemberProvider`)**: Returns information about the connected member and users.
5. **`metadataProvider` (`IMetadataProvider`)**: Retrieves available statuses, priorities, and activities.

// 2. Definição do DataSource (Metadata-Driven)
export const MeuDataSource: IDataSource = {
  getConnectionSchema(): AddonSettingsSchema {
    return [
      {
        id: 'credentials',
        label: 'Credenciais & Conexão',
        groups: [
          {
            id: 'auth',
            label: 'Autenticação',
            fields: [
              {
                id: 'serverUrl',
                label: 'URL do Servidor',
                type: 'text',
                scope: 'configuration',
                required: true,
              },
              {
                id: 'apiToken',
                label: 'Token de Acesso',
                type: 'password',
                scope: 'credential',
                required: true,
              },
            ],
          },
        ],
      },
    ]
  },

  createInstance(context: DataSourceContext): IDataSourceInstance {
    return {
      authStrategy: new MinhaAuthStrategy(context),
      tasksProvider: new MinhaApiTaskProvider(context),
      timeEntriesProvider: new MinhaApiTimeEntryProvider(context),
      membersProvider: new MinhaApiMemberProvider(context),
      metadataProvider: new MinhaApiMetadataProvider(context),
    }
  },
}

// 3. Addon Principal (Microkernel: apenas activate e deactivate)
export default class MeuDataSourceAddon implements IAddon {
  public async activate(context: AddonContext): Promise<void> {
    // Registra as preferências dinamicamente ou reaproveita o schema
    context.contributions.settings.register(MeuDataSource.getConnectionSchema())

    // Registra o DataSource no sistema
    context.contributions.dataSources.register(MeuDataSource)
  }

  public async deactivate(): Promise<void> {
    console.log('[MeuDataSourceAddon] Desativado.')
  }
}

## 💡 DataSource Best Practices

- **Separate Providers**: Put each responsibility (Tasks, Time Entries, Members, and Metadata) in a specialized class implementing the corresponding interface.
- **Respect Checkpoints**: Use modification-date filters (`checkpoint.updatedAt`) to minimize traffic during `pull`.
- **Validate Credentials**: Authenticate in `authStrategy` so invalid connections are rejected before synchronization begins.
- **Declare Settings**: Use `context.contributions.settings.register(...)` for credential and configuration fields without mixing them with network logic.
