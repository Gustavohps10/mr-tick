description: Autorize contas pelo navegador e conclua a conexão no aplicativo.

OAuth permite que o usuário autorize uma conta pelo navegador, sem entregar sua senha ao addon. PKCE acrescenta uma prova que vincula o código recebido à solicitação que iniciou a autorização.

Declare `auth` no manifesto. Para usar esse fluxo, registre um `AddonConnectionAuthenticator` com `method: oauth`. O Mr. Tick gera a prova PKCE e o identificador de segurança `state`, acompanha a tentativa e salva as credenciais. O addon implementa a comunicação com o serviço externo.

| Ambiente        | Endereço de retorno cadastrado no serviço | Página abre no desktop      |
| --------------- | --------------------------------------- | --------------------------- |
| Desenvolvimento | `http://localhost:3000/oauth/callback`  | `electron://oauth/callback` |
| Produção        | `https://mistertick.com/oauth/callback` | `mr-tick://oauth/callback`  |

Essas são as rotas usadas atualmente pelo addon do Discord. Cadastre no serviço externo o endereço HTTP da tabela; a página abre o aplicativo em seguida. Use o mesmo `redirectUri` ao trocar o código por credenciais. O protocolo interno `mr-tick-app://`, usado para recursos e ativação, tem outra finalidade.

1. Registre o perfil e o autenticador OAuth, incluindo seu `redirectUri` HTTP.
2. `core.connections.createAuthorizationRequest(scope)` fornece `state`, a prova PKCE (`codeChallenge`, com método S256) e o endereço de retorno ao autenticador.
3. O autenticador retorna `authUrl` e `timeoutMs`.
4. O serviço externo retorna à página HTTP; o aplicativo associa esse retorno à tentativa ativa.
5. `completeAuthentication` recebe o código, a prova original (`codeVerifier`), `state` e o endereço de retorno. Valide a resposta do serviço e retorne a identidade da conta e suas credenciais.
6. O aplicativo salva as credenciais e conclui a conexão.

A função abaixo cria somente o pedido de autorização. A troca do código por credenciais, a identificação da conta e a renovação dependem do serviço integrado:

```ts
import { Either, type AddonConnectionAuthenticator } from '@mr-tick/sdk'

type OAuthAuthenticator = Extract<
  AddonConnectionAuthenticator,
  { method: 'oauth' }
>

export function createAuthorizationRequest(
  clientId: string,
): OAuthAuthenticator['createAuthorizationRequest'] {
  return async (scope, parameters) => {
    void scope

    const url = new URL('https://provider.example/oauth/authorize')

    url.search = new URLSearchParams({
      client_id: clientId,
      response_type: 'code',
      redirect_uri: parameters.redirectUri,
      state: parameters.state,
      code_challenge: parameters.codeChallenge,
      code_challenge_method: parameters.codeChallengeMethod,
    }).toString()

    return Either.success({ authUrl: url.toString(), timeoutMs: 120000 })
  }
}
```

O `state` pertence a uma tentativa: ele não pode autorizar outra conexão nem reativar uma tentativa expirada. Não inclua segredos de aplicação (`client secrets`) em addons distribuídos aos usuários. Valide a resposta que contém os tokens antes de usá-la e devolva falhas pelo contrato `Either`.

`context.host.oauth` também oferece `generatePKCE`, `generateState` e `authorize` para operações com o navegador. `authorize` retorna `Promise<OAuthResult>`; ele não salva uma conexão por conta própria. Para conectar contas, siga o fluxo descrito acima.
